# 事件流与工具执行规范

> 对外用事件流（Channel）暴露 Agent 循环的完整过程；对内用工具分类 + 批量执行策略管理工具调用。Plan-only 模式提供"只规划不执行"的安全态。

---

## 1. 事件流设计

### 1.1 设计理念

采用事件流（Event Stream）作为 Agent 循环与上层（TUI/CLI）之间的通信机制：

- **单向广播** — 循环内部产出事件，外部按需消费
- **无阻塞** — 循环不等待消费者处理，事件发出即继续
- **全链路可观测** — 从用户消息到最终回复的每一步都有事件

### 1.2 Channel 概念

`Channel` 是一个事件管道接口，Agent 循环向 Channel `emit` 事件，上层从 Channel 订阅消费：

```
┌──────────────────────────────────────────────────────────┐
│                     Agent Loop                           │
│                                                         │
│   emit(event) ──────────▶ Channel ──────────▶ 消费者    │
│                                                         │
└──────────────────────────────────────────────────────────┘
        ▲                                    │
        │                                    ▼
  ┌──────────┐                      ┌──────────────┐
  │  TUI/CLI  │◀──── consume ───────│  Event Queue │
  └──────────┘                      └──────────────┘
```

**两种实现**：

| 实现 | 说明 | 适用场景 |
|------|------|---------|
| `SyncChannel` | handler 在 emit 时同步调用 | TUI（需要实时渲染） |
| `AsyncChannel` | 事件入队，消费者异步消费 | CLI 批量处理、日志记录 |

### 1.3 事件类型定义

| 事件类型 | 说明 | 触发时机 |
|---------|------|---------|
| `user_message` | 用户输入消息 | 收到用户消息，循环开始前 |
| `thinking` | 模型推理过程 | LLM 返回 thinking 内容时 |
| `text` | 模型文本回复 | LLM 返回文本内容时 |
| `tool_call_start` | 工具调用开始 | 开始执行某个工具时 |
| `tool_call_end` | 工具调用结束 | 某个工具执行完成时 |
| `tool_result` | 工具执行结果 | 一轮中所有工具执行完成后 |
| `turn_end` | 一轮结束 | 一轮执行完毕，准备下一轮或终止 |
| `final_reply` | 最终回复 | 循环终止时的最终输出 |
| `error` | 错误 | 任何不可恢复错误发生时 |
| `cancelled` | 用户取消 | 收到取消信号时 |
| `loop_end` | 循环结束 | 循环正常终止 |

### 1.4 事件数据结构

```typescript
// ── 事件基类 ──
interface Event {
  type: EventType;
  timestamp: number;       // 毫秒时间戳
  turn: number;            // 当前轮次（0-based）
  data: EventData;         // 类型特定数据
}

// ── 用户消息 ──
interface UserMessageEvent extends Event {
  type: "user_message";
  data: { content: string; role: "user" };
}

// ── 模型 thinking ──
interface ThinkingEvent extends Event {
  type: "thinking";
  data: { content: string };
}

// ── 模型文本 ──
interface TextEvent extends Event {
  type: "text";
  data: { content: string };
}

// ── 工具调用开始 ──
interface ToolCallStartEvent extends Event {
  type: "tool_call_start";
  data: {
    tool_call_id: string;
    tool_name: string;
    arguments: Record<string, any>;
    tool_type: "read" | "write";   // 读类 / 写类
  };
}

// ── 工具调用结束 ──
interface ToolCallEndEvent extends Event {
  type: "tool_call_end";
  data: {
    tool_call_id: string;
    tool_name: string;
    duration_ms: number;
    status: "success" | "error" | "timeout";
  };
}

// ── 工具结果 ──
interface ToolResultEvent extends Event {
  type: "tool_result";
  data: {
    tool_call_id: string;
    tool_name: string;
    result: any;
    is_error: boolean;
  };
}

// ── 一轮结束 ──
interface TurnEndEvent extends Event {
  type: "turn_end";
  data: {
    reason: "end_turn" | "no_tool_calls" | "max_turns" | "cancelled" | "error";
  };
}

// ── 最终回复 ──
interface FinalReplyEvent extends Event {
  type: "final_reply";
  data: { content: string };
}

// ── 错误 ──
interface ErrorEvent extends Event {
  type: "error";
  data: {
    message: string;
    error_type: string;      // "llm_api_error", "llm_parse_error", "llm_timeout"
    recoverable: boolean;
  };
}

// ── 取消 ──
interface CancelledEvent extends Event {
  type: "cancelled";
  data: { reason: string };
}

// ── 循环结束 ──
interface LoopEndEvent extends Event {
  type: "loop_end";
  data: {
    total_turns: number;
    termination_reason: string;
  };
}
```

### 1.5 事件流时序

**一轮典型执行的事件流：**

```
user_message ──────────────────────────────────────────────────────▶
thinking ────────────────────────────────────────────────────────────▶
text (可选) ─────────────────────────────────────────────────────────▶
tool_call_start (tool_A, read) ──────────────────────────────────────▶
tool_call_start (tool_B, read) ──────────────────────────────────────▶  ← 并发
tool_call_end (tool_A) ──────────────────────────────────────────────▶
tool_call_end (tool_B) ──────────────────────────────────────────────▶
tool_call_start (tool_C, write) ─────────────────────────────────────▶
tool_call_end (tool_C) ──────────────────────────────────────────────▶  ← 串行
tool_result (tool_A) ────────────────────────────────────────────────▶
tool_result (tool_B) ────────────────────────────────────────────────▶
tool_result (tool_C) ────────────────────────────────────────────────▶
turn_end (reason: continue) ────────────────────────────────────────▶
[下一轮...]
```

**最终终止轮的事件流：**

```
thinking ────────────────────────────────────────────────────────────▶
text ────────────────────────────────────────────────────────────────▶
final_reply ──────────────────────────────────────────────────────────▶
turn_end (reason: end_turn) ──────────────────────────────────────────▶
loop_end ────────────────────────────────────────────────────────────▶
```

**取消打断的事件流：**

```
user_message ────────────────────────────────────────────────────────▶
thinking ─────────────────────────────────────────────────────────────▶
tool_call_start (tool_A) ─────────────────────────────────────────────▶
                    ┌── cancel 信号到达 ──┐
                    │                     │
tool_call_end (tool_A, status: success) ──▶  ← 等待当前工具完成
cancelled (reason: "user_cancelled") ──────▶
loop_end (total_turns: 1) ─────────────────▶
```

## 2. 工具执行规范

### 2.1 工具分类

| 类别 | 说明 | 执行方式 | 示例 |
|------|------|---------|------|
| `read`（读类） | 不产生副作用，安全可并发 | 并发执行 | 查询数据、读取文件、搜索 |
| `write`（写类） | 产生副作用，需要互斥 | 串行执行 | 创建文件、修改配置、发送消息 |

### 2.2 工具注册接口

```typescript
interface ToolDefinition {
  name: string;
  description: string;
  type: "read" | "write";         // 工具类别
  parameters: JSONSchema;          // 参数 schema
  timeout_ms?: number;             // 可选超时覆盖，默认 30s
  execute: (args, context: ToolContext) => Promise<ToolResult>;
}

interface ToolContext {
  cancel_token: CancelToken;
  working_directory: string;
  session_id: string;
  // 后续可扩展：权限上下文、审计信息等
}

interface ToolResult {
  output: string;                  // 工具输出（文本）
  is_error: boolean;               // 是否出错
  metadata?: Record<string, any>;  // 可选元数据
}
```

### 2.3 批量执行策略

当一轮响应中包含多个 `tool_calls` 时：

```
输入: [tool_A(read), tool_B(read), tool_C(write), tool_D(write)]

执行顺序:
  Phase 1: 并发执行 [tool_A, tool_B]     ← 读类，asyncio.gather
  Phase 2: 串行执行 [tool_C → tool_D]     ← 写类，逐个执行

注意: Phase 1 全部完成后才开始 Phase 2
```

```python
async def execute_tools_batch(tool_calls, config, channel):
    # ── 1. 分类 ──
    read_calls = [tc for tc in tool_calls if registry.get(tc.name).type == "read"]
    write_calls = [tc for tc in tool_calls if registry.get(tc.name).type == "write"]

    results = []

    # ── 2. Phase 1: 读类并发 ──
    if read_calls:
        read_results = await asyncio.gather(
            *[execute_single(tc, config, channel) for tc in read_calls],
            return_exceptions=True
        )
        results.extend(zip(read_calls, read_results))

    # ── 3. Phase 2: 写类串行 ──
    for tc in write_calls:
        result = await execute_single(tc, config, channel)
        results.append((tc, result))

    return results
```

### 2.4 执行前后拦截位

在工具执行前后预留 hook 位置：

```
                    ┌─────────────┐
                    │  Pre-hook   │ ← 权限检查 / plan-only 检查
                    └──────┬──────┘
                           │ pass
                           ▼
                    ┌─────────────┐
                    │  执行工具    │ ← timeout 包裹
                    └──────┬──────┘
                           │
                           ▼
                    ┌─────────────┐
                    │  Post-hook  │ ← 审计日志 / 结果处理
                    └──────┬──────┘
                           │
                           ▼
                       返回结果
```

```python
async def execute_single(tool_call, config, channel):
    tool = registry.get(tool_call.name)

    # ── Pre-hook ──
    # plan-only 检查
    if config.plan_only and tool.type == "write":
        return ToolResult(
            output="当前为 plan-only 模式，写类工具已被拦截。"
                   "请关闭 plan-only 开关后再执行写操作。",
            is_error=True
        )

    # 权限检查位（本章留空，不实现具体规则）
    # permission_result = check_permission(tool_call, config)
    # if not permission_result.allowed:
    #     return ToolResult(output=permission_result.reason, is_error=True)

    # ── 发射开始事件 ──
    await channel.emit(Event(type="tool_call_start", data={
        "tool_call_id": tool_call.id,
        "tool_name": tool_call.name,
        "arguments": tool_call.arguments,
        "tool_type": tool.type,
    }))

    # ── 执行（带超时）──
    start_time = time.monotonic()
    try:
        result = await asyncio.wait_for(
            tool.execute(tool_call.arguments, context),
            timeout=tool.timeout_ms / 1000
        )
        status = "success"
    except asyncio.TimeoutError:
        result = ToolResult(output="工具执行超时", is_error=True)
        status = "timeout"
    except Exception as e:
        result = ToolResult(output=f"工具执行异常: {e}", is_error=True)
        status = "error"

    duration_ms = int((time.monotonic() - start_time) * 1000)

    # ── Post-hook ──
    # 审计日志位（本章留空）
    # log_audit(tool_call, result, config)

    # ── 发射结束事件 ──
    await channel.emit(Event(type="tool_call_end", data={
        "tool_call_id": tool_call.id,
        "tool_name": tool_call.name,
        "duration_ms": duration_ms,
        "status": status,
    }))

    return result
```

### 2.5 拦截位一览

| 拦截位 | 时机 | 用途 | 本章实现 |
|--------|------|------|:--------:|
| Pre-hook | 工具执行前 | 权限检查、plan-only 拦截 | 仅 plan-only 检查 |
| Post-hook | 工具执行后 | 审计日志、结果处理 | 留空 |

## 3. Plan-only 模式

### 3.1 设计目标

提供一个"只规划不执行"的安全模式：

- 进入后只允许读类工具
- 写类工具被拦截，返回提示信息
- 最终输出一份行动计划交还用户审批

### 3.2 切换机制

```python
@dataclass
class AgentConfig:
    # ...
    plan_only: bool = False   # 开关，默认关闭
```

- **进入 plan-only**：设置 `plan_only = True`
- **退出 plan-only**：设置 `plan_only = False`
- 可以在循环开始前设置，也可以在循环中途切换

### 3.3 行为规则

| 场景 | `plan_only=False` | `plan_only=True` |
|------|:------------------:|:----------------:|
| 读类工具 | 正常执行 | 正常执行 |
| 写类工具 | 正常执行 | 拦截，返回提示信息 |
| 最终输出 | 正常回复 | 附带行动计划摘要 |

### 3.4 计划输出格式

plan-only 模式下，循环结束后输出一份结构化计划：

```typescript
interface Plan {
  summary: string;                    // 计划概述
  steps: PlanStep[];                 // 步骤列表
  tools_blocked: BlockedToolCall[];   // 被拦截的写类工具调用记录
}

interface PlanStep {
  index: number;                     // 步骤序号
  action: string;                    // 动作描述
  tool_name: string;                 // 涉及的工具
  arguments: Record<string, any>;    // 工具参数
  rationale: string;                 // 为什么需要这步
  risk_level: "low" | "medium" | "high";
}

interface BlockedToolCall {
  tool_name: string;                 // 被拦截的工具名
  arguments: Record<string, any>;    // 工具参数
  reason: string;                    // "plan-only 模式下写类工具被拦截"
}
```

### 3.5 Plan-only 交互流程

```
用户: "帮我重构 auth 模块"
                    │
                    ▼
         ┌─────────────────────┐
         │ plan_only = True    │
         │ Agent 循环运行       │
         │  ├── 读类工具 ✅ 执行 │  ← 读取文件、搜索代码
         │  └── 写类工具 ❌ 拦截 │  ← 创建文件、修改代码
         └──────────┬──────────┘
                    │
                    ▼
         ┌─────────────────────┐
         │ 输出 Plan            │
         │  ├── summary          │
         │  ├── steps[]          │
         │  └── tools_blocked[] │
         └──────────┬──────────┘
                    │
                    ▼
              用户审批计划
              ├── 批准 → 关闭 plan_only → 重新执行
              └── 修改 → 调整后重新规划
```

def on_event(event: Event):

### 4.2 CLI 消费示例

```python
def on_event(event: Event):
    match event.type:
        case "thinking":
            print(f"[thinking] {event.data['content']}")
        case "text":
            print(event.data["content"])
        case "tool_call_start":
            print(f"[tool] {event.data['tool_name']}({event.data['arguments']})")
        case "tool_result":

            print(f"[result] {status} {event.data['result']}")
        case "error":
            print(f"[error] {event.data['message']}")
        case "final_reply":
            print(f"\n{event.data['content']}")
```

## 5. Channel 接口定义

```python
from abc import ABC, abstractmethod

class Channel(ABC):
    """事件流管道接口"""

    @abstractmethod
    async def emit(self, event: Event):
        """发射事件"""
        pass

    @abstractmethod
    def subscribe(self, handler: Callable[[Event], None]):
        """订阅事件"""
        pass

    @abstractmethod
    def unsubscribe(self, handler: Callable[[Event], None]):
        """取消订阅"""
        pass


class SyncChannel(Channel):
    """同步 Channel：handler 在 emit 时同步调用"""

    def __init__(self):
        self._handlers: list[Callable[[Event], None]] = []

    async def emit(self, event: Event):
        for handler in self._handlers:
            handler(event)

    def subscribe(self, handler):
        self._handlers.append(handler)

    def unsubscribe(self, handler):
        self._handlers.remove(handler)


class AsyncChannel(Channel):
    """异步 Channel：事件入队，消费者异步消费"""

    def __init__(self, maxsize: int = 1000):
        self._queue: asyncio.Queue[Event] = asyncio.Queue(maxsize=maxsize)

    async def emit(self, event: Event):
        await self._queue.put(event)

    async def consume(self):
        """异步迭代器，逐个消费事件"""
        while True:
            event = await self._queue.get()
            yield event
            self._queue.task_done()

    def subscribe(self, handler):
        asyncio.create_task(self._consumer_loop(handler))

    async def _consumer_loop(self, handler):
        async for event in self.consume():
            handler(event)
```
