# ZXCode 纵深防御安全检查验收清单

> 每一项都必须可观察、可勾选。测试命令统一使用：
> `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`

---

## 一、配置与模式

- [ ] 项目根目录存在 `zxcode-security.toml`。
- [ ] 配置文件可以表示三档模式：`strict`、`default`、`allow`。
- [ ] 严格模式下，除明确允许外的操作都被拒绝。
- [ ] 默认模式下，未命中规则时会询问用户。
- [ ] 放行模式下，未命中规则时直接放行。
- [ ] 黑名单在 `strict`、`default`、`allow` 三档模式下都保持生效。

## 二、覆盖范围

- [ ] 第一版只覆盖 `Bash`、`WriteFile`、`EditFile`。
- [ ] `ReadFile`、`Glob`、`Grep` 在第一版里不受这套新策略强制拦截。
- [ ] 新增策略不会改变现有工具的函数签约。

## 三、硬黑名单

- [ ] 危险 shell 命令会在执行前被拦截。
- [ ] 远程脚本直执行模式会在执行前被拦截。
- [ ] 明确越权路径会在执行前被拦截。
- [ ] 明确危险的覆盖写会在执行前被拦截。
- [ ] 被黑名单拦截时，返回结果包含可读原因。

## 四、路径沙箱

- [ ] `WriteFile` 只能写入允许目录内的路径。
- [ ] `EditFile` 只能编辑允许目录内的路径。
- [ ] `Bash` 中指向允许目录外的绝对路径会被拒绝或询问。
- [ ] 路径里出现 `..` 的越权尝试会被拦截。
- [ ] 符号链接逃逸不会绕过路径沙箱。

## 五、规则优先级

- [ ] 会话级临时规则优先于项目级规则。
- [ ] 项目级规则优先于用户全局默认。
- [ ] 用户全局默认优先于模式兜底。
- [ ] 未命中任何明确规则时，默认行为是询问用户。

## 六、HITL

- [ ] 规则未命中时会弹出或返回确认请求。
- [ ] 用户可以选择“本次允许”。
- [ ] 用户可以选择“本会话允许”。
- [ ] 用户可以选择“永久允许”。
- [ ] 本次允许只影响当前一次调用。
- [ ] 本会话允许只影响当前会话。
- [ ] 永久允许会写回 `zxcode-security.toml`。
- [ ] 永久允许只写入精确命令签名或精确路径签名。

## 七、永久允许写回

- [ ] 允许 `git commit` 之后再次运行时不重复确认。
- [ ] 允许记录不会自动扩散到相似命令。
- [ ] 写回配置后，重启仍然生效。
- [ ] 配置文件中可以看出被允许的具体签名。

## 八、调度层与工具层双重防护

- [ ] 调度层可以在工具执行前短路拦截。
- [ ] 工具层仍保留自己的路径或命令兜底检查。
- [ ] 任一层拦截时，实际执行不会发生。
- [ ] 拦截原因在调度层和工具层都可观测。

## 九、端到端验收

- [ ] 输入一个高危 shell 命令，能看到明确拦截。
- [ ] 输入一个越权文件写入，能看到明确拦截。
- [ ] 输入一个默认模式下的未命中命令，能看到询问。
- [ ] 选择本会话允许后，同类命令在本会话内不再重复询问。
- [ ] 选择永久允许后，重启后仍然不再重复询问。
- [ ] `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` 全部通过，`FAILED` 和 `ERROR` 计数均为 `0`。
