# ZXCode 提示词编排与缓存分层验收清单

> 每一项都必须可观察、可勾选。测试命令统一使用：
> `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`

---

## 一、稳定模块

- [ ] `zxcode/prompts.py` 存在，并定义了提示词模块数据结构。
- [ ] 默认稳定模块至少包含 6 类内容：`identity`、`behavior`、`coding`、`safety`、`tools`、`output`。
- [ ] 构造稳定前缀时，模块先按优先级升序，再按模块名升序排序。
- [ ] 两次传入相同模块但顺序不同，生成的稳定前缀字符串完全相同。
- [ ] 空内容模块不会出现在稳定前缀中。
- [ ] 稳定前缀中不包含当前工作目录字符串。
- [ ] 稳定前缀中不包含当前时间字符串。
- [ ] 稳定前缀中不包含 Git 分支名或 Git 工作区状态。

## 二、外置模块

- [ ] 项目内提示词模块目录不存在时，程序仍能正常启动并使用内置默认模块。
- [ ] 提示词模块目录存在且包含 1 个 Markdown 文件时，该文件内容出现在稳定前缀中。
- [ ] 提示词模块文件名改变后，稳定排序仍按优先级和模块名确定。
- [ ] 读取到空 Markdown 文件时，该文件不会让稳定前缀出现空章节。
- [ ] 外置模块加载不需要新增第三方依赖。

## 三、动态环境消息

- [ ] 动态环境消息单独作为一条消息加入请求，不拼入稳定 system 内容。
- [ ] 动态环境消息包含工作目录。
- [ ] 动态环境消息包含操作系统信息。
- [ ] 动态环境消息包含当前时间。
- [ ] Git 仓库可用时，动态环境消息包含轻量 Git 摘要。
- [ ] Git 不可用或当前目录不是仓库时，构造请求不报错。
- [ ] 动态环境消息不包含 `LLM_API_KEY` 的值。
- [ ] 动态环境消息不包含任何环境变量名中带 `KEY`、`TOKEN`、`SECRET`、`PASSWORD` 的值。

## 四、请求消息顺序

- [ ] `ChatSession.request_messages("hi")` 返回的第一条消息是稳定 system 消息。
- [ ] 动态环境消息排在稳定 system 消息之后。
- [ ] 历史消息排在稳定前缀和动态环境消息之后。
- [ ] 当前用户消息始终是最后一条。
- [ ] `commit_messages` 的行为不变：仍先追加用户消息，再追加 assistant/tool 消息。
- [ ] `/clear` 后历史消息为空，但稳定前缀和动态环境消息仍会在下一次请求中生成。

## 五、plan-only 分层

- [ ] `plan_only=False` 时，请求消息中不包含 plan-only 提示。
- [ ] `plan_only=True` 时，请求消息中包含独立的 plan-only 动态提示消息。
- [ ] `plan_only=True` 时，稳定前缀字符串与 `plan_only=False` 时完全相同。
- [ ] plan-only 写工具拦截行为保持不变：写类工具不执行，返回 `plan_only_blocked`。
- [ ] `AgentComplete.blocked_calls` 仍能记录被拦截的写工具调用。

## 六、工具规则强化

- [ ] 稳定前缀的工具使用模块包含 `ReadFile`、`WriteFile`、`EditFile`、`Bash`、`Glob`、`Grep` 六个工具名。
- [ ] 稳定前缀明确写明搜索文件优先用 `Glob` 或 `Grep`。
- [ ] 稳定前缀明确写明读取文件优先用 `ReadFile`。
- [ ] 稳定前缀明确写明编辑前必须先读取目标文件。
- [ ] `Glob` 的工具描述仍包含自动排除 `.git`、`node_modules`、`vendor`、`.idea`、`__pycache__` 的规则。
- [ ] `Bash` 的工具描述仍表达非明确只读命令需要确认。

## 七、缓存分层

- [ ] 改变工作目录后，稳定前缀完全不变。
- [ ] 改变当前时间后，稳定前缀完全不变。
- [ ] 改变 Git 状态后，稳定前缀完全不变。
- [ ] 增加一轮历史对话后，稳定前缀完全不变。
- [ ] 开启或关闭 plan-only 后，稳定前缀完全不变。
- [ ] 请求前缀的第一条稳定 system 消息在连续两轮普通对话中逐字节一致。

## 八、端到端验收

- [ ] 启动命令仍为 `.\.venv\Scripts\python.exe -m zxcode`。
- [ ] 真实或伪造 LLM 客户端完成一轮普通对话，界面能显示流式回答。
- [ ] 真实或伪造 LLM 客户端完成一轮工具调用对话，工具定义仍正常传给模型。
- [ ] 打开 `/plan` 后再发起一轮请求，界面仍显示 plan-only 状态。
- [ ] `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` 全部通过，`FAILED` 和 `ERROR` 计数均为 `0`。
- [ ] README 中能找到提示词分层说明。
