# ZXCode 提示词编排与缓存分层规格

## 背景

ZXCode 现在已经具备终端多轮对话、流式输出、工具调用、Agent loop、plan-only 模式和六个内置工具。当前系统提示词仍然是一个很小的固定字符串，环境信息、工具规则、模式提醒和未来章节指令还没有形成清晰边界。

随着后续功能增加，全局指令会越来越长。如果稳定规则、动态环境和会话开关混在同一段内容里，每次工作目录、时间、Git 状态或模式变化都会改变请求前缀，降低兼容服务的 prompt caching 命中机会，也会让规则维护变成“一坨字符串反复补丁”。

本章只解决提示词编排与缓存分层的第一层：把稳定指令拆成可排序模块，和变化内容分开拼装，保证稳定前缀长期保持稳定。

## 目标用户

- 使用 ZXCode 做多轮编程任务，希望模型稳定遵循项目规则、工具规则和输出风格的开发者。
- 后续要继续给 ZXCode 增加章节能力，希望新规则可以按职责插入，而不是修改一整段全局提示词的维护者。
- 使用 OpenAI-compatible 服务并希望自然利用 prompt caching 的用户。

## 能力清单

- 全局指令按职责拆成多个稳定模块，并按优先级稳定排序。
- 稳定模块支持代码内置默认内容，也支持从项目内提示词文件追加扩展。
- 稳定内容始终出现在请求消息最前面，且在环境变化时内容和顺序不变。
- 动态环境信息从全局指令中移出，作为单独的运行时补充消息加入请求。
- 工具使用关键规则同时出现在稳定全局指令和工具描述中，强化模型对专用工具的偏好。
- 会话级开关的提示词不进入稳定前缀，由运行时按当前状态动态注入。
- 对话历史继续保持在稳定前缀与当前用户输入之后的正常上下文区域。
- 第一版采用供应商中立策略，不依赖特定缓存 API。

## 非功能要求

- **稳定性**：同一版本代码在相同提示词文件下，稳定前缀的模块顺序和文本内容保持确定。
- **兼容性**：继续使用 OpenAI-compatible chat messages 形态，不更换 API，不引入新的运行时依赖。
- **可维护性**：新增提示词模块时只需要增加模块内容和优先级，不需要手写拼接大字符串。
- **安全性**：动态环境信息不得包含 API Key、token、完整敏感环境变量或其它凭据。
- **可观测性**：测试可以直接断言稳定前缀在环境变化前后不变。
- **最小改动**：不重写 Agent loop，不调整工具执行语义，不引入缓存指标抽象层。

## 设计骨架

### 分层模型

请求上下文分为三层。

第一层是稳定前缀，包含身份、行为原则、代码规范、安全边界、工具使用原则、输出风格等长期规则。稳定前缀由多个模块按优先级拼成一个或多个 system 消息，要求环境变化和会话开关变化都不改变这一层。

第二层是动态补充，包含当前工作目录、操作系统、当前时间、Git 状态等运行时信息。它作为独立补充消息放在稳定前缀之后，不污染稳定前缀。

第三层是会话内容，包含历史用户消息、模型回复、工具结果和当前用户输入。它保持现有多轮对话语义。

### 模块来源

第一版采用混合方案。核心稳定模块由代码提供默认值，保证没有外部文件时也能启动。项目内可以提供可编辑的提示词模块文件，用于追加或覆盖项目级规则。外部文件只承担内容扩展，不承担复杂脚本逻辑。

### 排序规则

每个稳定模块拥有职责分类和优先级。拼装时先按优先级排序，再按模块名做稳定排序，保证同样输入总是得到同样输出。模块之间用固定分隔符连接，避免文案粘连。

### 缓存策略

第一版不直接调用供应商专用缓存控制字段。缓存策略只依赖一个原则：稳定内容固定地排在请求最前面，动态内容放在后面。支持 prompt caching 的兼容服务可以自然复用稳定前缀；不支持缓存的服务也能正常工作。

### 工具规则强化

工具通用规则放入稳定前缀，例如优先使用专用读写搜索工具、编辑前先读取目标文件、危险操作需要确认。每个工具自己的描述继续写清自身能力、边界、只读/写入属性和参数要求。两处表达同一类关键约束，但不重复实现逻辑。

### 动态信息

环境信息作为运行时补充消息生成。第一版只要求结构清晰、可测试、无敏感信息，不要求把 Git 状态做成完整报告。环境信息变化不应导致稳定前缀变更。

## 完成定义

- 稳定提示词模块已从现有会话构造逻辑中拆出，并可按优先级拼装。
- 项目内提示词文件可被加载，并参与稳定前缀拼装。
- 环境信息以独立动态消息加入请求，不再写入稳定全局指令。
- plan-only 等会话开关提示不进入稳定前缀。
- 内置工具规则在稳定全局指令和工具描述中都有明确表达。
- 单元测试覆盖稳定排序、外置模块加载、环境变化不影响稳定前缀、请求消息顺序。
- 现有 Agent loop、工具调用、流式输出和启动命令保持可用。

## Out of Scope

- 不实现运行中带特殊标签的补充指令注入机制。
- 不实现首轮完整、间隔轮次重复完整、其余轮次精简的模式提醒节奏。
- 不解析供应商返回的缓存命中字段。
- 不新增 `CacheMetrics` 或供应商适配层。
- 不重写工具执行器、权限系统或 Agent loop 终止逻辑。
- 不做长期记忆、上下文压缩或历史摘要。
- 不把提示词模块做成插件系统。
