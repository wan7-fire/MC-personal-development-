# ZXCode 上下文压缩验收清单

> 每一项都必须可观察、可勾选。测试命令统一使用：
> `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`

---

## 一、配置与估算

- [ ] `zxcode/compress.py` 存在，提供 `CompressionConfig`。
- [ ] 默认 `context_window = 131072` token、`trigger_ratio = 0.8`、`target_ratio = 0.4`。
- [ ] 默认 `single_result_limit = 8192` 字符、`batch_total_limit = 32768` 字符。
- [ ] 默认 `breaker_limit = 2` 次、`summary_model = None`（空时复用当前模型）。
- [ ] `estimate_tokens("a" * 4000) == 1000`（字符数 // 4）。
- [ ] `spool_dir` 默认解析为项目根下 `.zxcode/spool`。

## 二、一层：单条落盘

- [ ] 构造 content 长度 9000 字符的 tool 消息，经过一层后 content 含「已溢出」标记、原长度、`.zxcode/spool/<sha256>.txt` 相对路径、≤200 字符开头预览。
- [ ] 落盘文件内容与原 content 逐字节一致。
- [ ] 同一内容重复落盘只生成一个文件（文件名 = content sha256）。
- [ ] content 长度 ≤ 8192 字符的 tool 消息原样保留，不落盘。

## 三、一层：合计控制

- [ ] 同一轮进入历史的工具消息合计 40000 字符（单条均 < 8192）时，从最大的一条开始落盘，直到合计 ≤ 32768 字符。
- [ ] 落盘后对话内保留的合计长度 ≤ `batch_total_limit`。
- [ ] 对已落盘的消息再次执行一层，结果逐字节一致（幂等）。
- [ ] 写盘失败（如目录不可写）时不修改原消息、不抛异常。

## 四、一层：会话兜底

- [ ] 往 `ChatSession.messages` 注入一条 20000 字符的旧 tool 消息，`prepare_request()` 后该消息已落盘。
- [ ] 连续调用两次 `prepare_request()`，返回的请求消息逐字节一致。

## 五、二层：摘要调用约束

- [ ] 摘要请求的 `tools` 参数为空（fake client 断言请求体无 `tools` 键）。
- [ ] 摘要 prompt 前 1/3 与后 1/3 各包含一次「禁止使用任何工具」。
- [ ] 摘要 prompt 包含 9 个固定栏目名：主要请求、关键概念、文件代码、错误修复、解决过程、用户原话、待办、当前工作、下一步。
- [ ] 模型输出缺少摘要标记 → 判定失败，不修改历史。

## 六、二层：替换与边界

- [ ] 历史估算 ≥ 131072 × 0.8 token 时自动触发压缩。
- [ ] 压缩后历史估算 ≤ 131072 × 0.4 token。
- [ ] 摘要为单条 user 角色消息，替换掉从最旧开始的若干完整轮次。
- [ ] 摘要「用户原话」栏目逐字包含被压缩用户消息的原文句子。
- [ ] 摘要消息后紧跟边界消息，文本精确为：
  `[上下文已压缩] 较早的历史已被结构化为摘要。如需文件、代码或错误信息的具体细节，请使用 ReadFile / Grep 重新读取对应文件或输出，不要根据摘要猜测内容。`
- [ ] 摘要失败（模型异常 / 解析失败 / 压缩后仍超限）时，历史与压缩前逐字节一致。
- [ ] 被替换消息引用的落盘文件在替换成功后已被删除。

## 七、熔断

- [ ] 摘要连续失败 2 次后，自动触发被短路：再逼近窗口时不发起摘要调用（fake client 计数不增加）。
- [ ] 手动 `/compact` 在熔断状态下仍然发起摘要。
- [ ] 短路后一次成功即复位，自动触发恢复。

## 八、手动命令

- [ ] `/help` 文案包含 `/compact`。
- [ ] 空会话执行 `/compact`，提示「没有可压缩的内容」。
- [ ] 大历史执行 `/compact`，提示包含替换的消息条数。
- [ ] 摘要失败时执行 `/compact`，提示包含失败原因且原历史不变。

## 九、一致性

- [ ] 循环内发生压缩后，`AgentComplete.final_history` 反映压缩结果。
- [ ] `generate` 用 `final_history` 重建的 `session.messages` 不含 system 角色消息（稳定前缀 / 环境消息 / plan-only 均被剥离）。
- [ ] plan-only 开启时重建结果正确（额外 system 消息不泄漏进会话）。
- [ ] 下一轮请求的稳定前缀与动态环境消息顺序、内容与压缩前一致（不破坏缓存分层）。

## 十、端到端验收

- [ ] 伪 LLM + 超大工具结果：模型下一轮能看到落盘路径，并用 ReadFile 读回完整内容（内容逐字节一致）。
- [ ] 长会话自动压缩：历史接近上限时出现摘要 + 边界消息，之后请求估算不超过 131072 × 0.4 token。
- [ ] `/compact` 手动压缩后出现成功/失败反馈。
- [ ] 连续失败后自动触发停止、手动触发可用、成功一次后恢复。
- [ ] `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` 全部通过，`FAILED` 和 `ERROR` 计数均为 `0`。
