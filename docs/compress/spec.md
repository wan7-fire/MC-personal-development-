# ZXCode 上下文压缩规格

## 背景

ZXCode 的每次请求都会把整段会话历史发给模型，而历史的主体通常是工具结果：一次大文件读取或大范围搜索就能产生数万字符，多轮累积后很快逼近窗口上限，导致早期内容被截断或对话被迫清空。现有的清空命令是粗暴手段，会丢掉任务的来龙去脉。

这一章要做一套两层压缩机制：第一层在源头预防，把超大的工具结果落到磁盘，对话里只留预览和读取路径；第二层在累积长度逼近窗口时兜底，用模型生成的结构化摘要替换最早的历史。压缩以「用户原始消息不被改写」为底线。

## 目标用户

- 长时间多轮工作、历史里堆了大量工具结果的开发者。
- 经常运行大输出工具（大文件读取、全库搜索、长日志）的使用者。
- 不想因为上下文超限就清空对话、丢失任务上下文和用户原话的用户。

## 能力清单

- 单条工具结果超过阈值时，完整内容落盘，对话中只保留预览与文件位置。
- 同一轮进入历史的工具结果合计体积受控，超限时从最大的开始依次落盘。
- 用户原始消息绝不被摘要改写；需要压缩时以原句摘录形式进入摘要。
- 整体历史逼近窗口上限时，自动调用模型生成结构化摘要，替换最早的旧消息。
- 摘要按固定栏目组织，覆盖主要请求、关键概念、文件代码、错误修复、解决过程、用户原话、待办、当前工作、下一步。
- 摘要调用明确禁止工具调用，并要求先输出分析草稿再输出正式摘要，草稿即用即弃。
- 压缩完成后追加一条边界消息，提示模型如需细节应重新读取文件，不得凭摘要臆造代码。
- 用户可以通过命令手动触发压缩。
- 摘要连续失败时熔断，停止自动触发，避免反复调用形成死循环。
- 每次 API 请求前按固定顺序执行两层：先轻量预防（管单条消息体积），再昂贵兜底（管累积历史长度）。

## 非功能要求

- **安全性**：落盘内容只写入项目内受控位置，文件名不可被内容控制；摘要与落盘过程不得把密钥或敏感环境变量写入对话或文件。
- **可解释性**：每次落盘、压缩、熔断都有可读的原因或提示。
- **可审计性**：落盘文件的路径可追溯；被替换的旧消息所引用的落盘文件随之清理。
- **幂等性**：同一历史重复执行预防层结果一致，已落盘消息不会二次落盘。
- **容错性**：摘要调用任何失败都不能修改原历史；熔断后手动触发仍然可用。
- **一致性**：模型在请求中看到的历史，与会话持久化保存的历史必须一致。
- **兼容性**：稳定前缀与动态环境消息保持不变，不破坏既有提示词缓存分层。
- **性能**：预防层必须是廉价纯本地操作；兜底层只在必要时调用模型。

## 设计骨架

### 两层流水线

每次请求前按固定顺序执行：

1. 预防层：检查单条工具结果与同一轮工具结果合计体积。超限内容写入项目内一个隐藏目录，对话中替换为预览与读取路径；该层纯本地、幂等。
2. 兜底层：估算累积历史长度。逼近窗口上限且未熔断时，从最旧的完整轮次开始切块，调用模型生成结构化摘要替换；压缩后历史必须明显低于窗口上限。

### 落盘与读取

被替换的工具结果按内容寻址写入项目内隐藏目录，文件名可复现。预览必须包含原长度、文件路径与开头片段；模型需要细节时按路径重新读取。被替换消息对应的落盘文件随之清理，清空会话时清理整个目录。

### 摘要与边界消息

摘要以单条用户消息的形式替换被切掉的旧消息，按固定栏目组织；其中「用户原话」栏目逐字保留被压缩用户消息的原文，不做改写。压缩完成后紧跟一条边界消息，提示模型按需重读文件。

### 摘要调用约束

摘要调用使用当前模型（可配置独立模型）。调用在接口层面不携带任何工具定义，提示词首尾各强调一次禁止调用工具，并要求先输出分析草稿、再输出正式摘要；草稿不进入会话。

### 熔断

摘要连续失败达到阈值后，自动触发被短路，避免反复调用模型；一次成功即复位。手动触发不受熔断限制。

### 手动触发

用户可通过命令在任意时刻手动执行两层压缩；无可压缩内容或压缩失败时给出明确提示。

## 完成定义

- 预防层在工具结果进入历史前生效，单条与合计两条体积规则均可观测。
- 兜底层在历史逼近窗口上限时自动触发，压缩后历史显著缩小。
- 摘要包含全部固定栏目，用户原话逐字保留。
- 摘要调用不带工具定义；模型结果中出现工具调用特征时判定为失败。
- 压缩成功后会话中紧跟边界消息。
- 摘要连续失败会熔断；熔断后自动触发停止、手动触发可用。
- 用户命令可手动压缩，成功、无需、失败三种情况都有明确反馈。
- 任何摘要失败都不改动原历史；模型看到的历史与持久化历史一致。
- 端到端验证覆盖：落盘预览、自动摘要、手动压缩、熔断恢复。

## Out of Scope

- 不引入真实 tokenizer，体积估算用字符近似。
- 不压缩思考/推理增量。
- 不做跨会话的压缩历史持久化。
- 不做可自定义的摘要模板 DSL。
- 不做异步后台压缩。
- 不改写用户原始消息本身，只允许原句摘录。
