# ZXCode 外部 MCP 服务器接入规格

## 背景

ZXCode 目前只提供六个内置工具，能力边界固定在工作目录内的文件、搜索与 PowerShell 命令。开发者希望让 Agent 调用外部 server 提供的专用能力（数据库、HTTP API、内部服务等），就像调用内置工具一样。这些外部 server 以 JSON-RPC 2.0 消息格式通信，并分为本地子进程与远程 HTTP 两类传输。

本规格定义 ZXCode 作为 MCP（Model Context Protocol）客户端接入外部 server 的最小闭环：连接握手、工具发现、工具调用，以及把远端工具无感接入现有工具中心。

现状约束：项目已有 Tool 接口、工具注册表、执行器、安全策略与 Agent 循环；本功能必须复用这些已有部件，不重写 Agent 循环，不引入新的第三方运行时包。

## 目标用户

- 使用 ZXCode 处理代码项目、同时希望模型能调用项目外专用服务的开发者。
- 拥有或能启动 MCP 兼容 server（本地命令行程序或远程 HTTP 服务）的用户。
- 希望远端工具像内置工具一样被发现、被确认、被审计，而不被特殊对待的用户。

## 能力清单

- 通过 JSON-RPC 2.0 消息格式与外部 server 双向通信。
- 支持两种传输：本地子进程 stdio 与远程 Streamable HTTP。
- 一次连接按「初始化握手 → 工具列表发现 → 工具调用」三阶段推进。
- 请求携带唯一 id，响应按 id 异步匹配，支持同一连接上的并发请求。
- 把发现的远端工具适配成 ZXCode 现有 Tool 接口并注册进工具中心，Agent 调用无感。
- 多个 server 的连接按名称缓存复用，避免每次工具调用都重新握手。
- 同名工具以「server 名 + 下划线 + 工具名」命名，避免注册冲突。
- 在项目配置文件中声明 server 列表（传输类型、启动命令或 URL、环境变量、超时），敏感值只经环境变量注入。
- 远端工具复用现有安全策略：只读分类、确认/拒绝、plan-only 拦截、每 server 工具禁用清单。
- 远端调用的超时、输出截断与取消遵循与内置工具一致的语义。

## 非功能要求

- 安全性：凭据与敏感值不得进入日志、会话历史或提示词；远端工具的描述与只读标注视为不可信，默认按写工具处理；确认界面必须展示 server 名与工具名。
- 响应性：每个请求都有超时；超时或用户取消后立即清理挂起请求，不悬挂；进程退出时统一关闭所有连接与子进程。
- 兼容性：现有六个内置工具、纯文本对话、快捷键、plan-only 与安全配置行为不回归；不引入新的第三方运行时包。
- 可测试性：核心行为通过仿造 server 与无头 UI 测试验证，不依赖真实网络或真实外部服务。
- 可观测性：连接建立/关闭与工具调用开始/结束进入现有事件流；日志包含 server 名、工具名、耗时与状态，不含敏感值。
- 可维护性：传输层与协议层分离，新增一种传输不重写协议与适配逻辑；配置、连接池、适配、安全各自独立成层。

## 设计骨架

### 分层

- 传输层：stdio 与 Streamable HTTP 两种实现，负责字节流与 HTTP 会话细节，向上提供统一的收发原语。
- 协议层：JSON-RPC 2.0 消息编解码、id 生成、挂起请求表、超时与错误映射。
- 会话层：初始化握手与协议版本协商、能力声明、连接状态机、重连与关闭。
- 适配层：把 server 声明的工具映射为本地 Tool 接口（描述、输入 schema、只读性、命名），并把调用结果与协议错误映射为统一结果。
- 装配层：读取配置文件、构建并缓存连接、启动时注册远端工具、退出时统一关闭。

### 关键流程

- 首次工具调用前：按配置连接对应 server → 握手并协商协议版本 → 拉取工具列表 → 注册可用工具。
- 调用时：复用已缓存连接，按 id 发送请求，等待匹配响应或超时；只读调用可与同批只读调用并发，写调用串行。
- 退出时：关闭所有 HTTP 连接；对 stdio 子进程先关闭输入、等待退出，必要时终止进程树。
- 连接失败：本次调用返回结构化失败，后续调用重新建立连接并刷新工具列表。

### 数据与错误

- 协议错误（JSON-RPC error 对象）与执行错误（结果中的错误标记）分别映射为统一结果中的失败信息。
- 工具输出按现有规则截断，避免无限内容进入模型上下文。
- server 主动发送的通知、过期响应与未知 id 响应被安全忽略，不中断连接。

### 安全边界

- 只读判定默认保守：只有受信 server 的只读标注或配置显式声明才按只读放行，其余一律视为写工具，走确认流程。
- plan-only 模式拦截所有写类远端工具。
- 配置支持每 server 的工具禁用清单与显式只读清单。
- 敏感值仅通过环境变量引用，不进入配置文件明文与日志。

## 完成定义

- 通过配置文件声明至少一个 stdio server 与一个 HTTP server，均能完成「握手 → 发现 → 调用」全流程。
- 远端工具与内置工具一起出现在注册表与模型可见工具列表中，调用全程不修改 Agent 循环。
- 同名工具以 server 名前缀区分，注册无冲突。
- 同一 server 的多次工具调用复用同一连接；进程退出时所有连接被关闭。
- 超时、取消、连接失败与协议错误均产生结构化失败结果，且不阻塞同批其它工具。
- 自动化测试覆盖双传输、id 匹配、并发、超时、取消、错误映射、配置解析、重名、安全拦截与输出截断。
- 端到端验证：模型完成「请求 → 远端工具调用 → 结果回传 → 基于结果的最终回复」完整循环。

## Out of Scope

- 消费或转发 server 通知（日志、进度、工具列表变更）。
- 响应 server 发起的客户端请求（采样、roots、elicitation 等）。
- resources、prompts、completions 等非工具能力。
- 独立 SSE 传输，以及 Streamable HTTP 的可选 GET 事件流（服务端主动下推）。
- 断线会话恢复与跨进程连接持久化。
- 工具自动发现与目录扫描。
- OAuth 等完整认证流程（仅支持静态请求头/环境变量凭据）。
- 图片、音频等非文本工具内容类型的渲染。
- 配置文件热重载与 server 管理命令界面。
