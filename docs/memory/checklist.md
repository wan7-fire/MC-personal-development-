# ZXCode 上下文记忆系统验收清单

## 指令文件

- [ ] 项目根放置 `ZXCODE.md`（UTF-8），新会话首条请求的 messages 中，对话开头包含该文件内容（断言抓取请求）。
- [ ] 用户级 `~/.zxcode/AGENTS.md` 存在时，其内容也出现在请求中，且位于项目级内容之后。
- [ ] 请求中项目级指令内容先于用户级指令内容出现。
- [ ] `ZXCODE.md` 缺失或不可读时启动不报错，请求中无对应指令段。
- [ ] 指令文件内容超过 32,000 字符时截断注入，并在界面显示截断提示。
- [ ] `/clear` 后下一条请求开头仍包含注入的指令消息。

## @include 引用

- [ ] `ZXCODE.md` 内 `@include sub/guide.md`（相对当前文件所在目录）时，`sub/guide.md` 内容被展开注入。
- [ ] 嵌套深度达到 4 层时，第 4 层引用被跳过，界面显示一条警告，启动不崩溃。
- [ ] 循环引用（A 引 B、B 引 A）被检测，重复展开被跳过并显示警告。
- [ ] `@include ../outside.md`、`@include C:\...`（绝对路径）被拒绝并显示警告。
- [ ] 引用目标为符号链接且解析后跳出所属根目录时被拒绝并显示警告。
- [ ] 项目级文件引用用户级目录文件被拒绝并显示警告。
- [ ] 被跳过的引用行在最终注入内容中不残留原文。

## 会话存档

- [ ] 每轮提交后，`~/.zxcode/sessions/<id>.jsonl` 按消息顺序每行一个 JSON 对象，行数与消息数一致。
- [ ] 同一会话多次追加后，文件仍是合法 JSONL，每行可独立 `json.loads`。
- [ ] 追加中途强制中断（或注入写失败）后，除最后一行外其余行均可解析。
- [ ] `<id>.meta.json` 存在，且包含字段：id、标题、摘要、消息数、created_at、updated_at、model。
- [ ] 标题等于首条用户消息截断到 60 字符。
- [ ] 消息数随每轮提交更新；列表展示只读 meta 文件（用文件访问探针断言未读取 `.jsonl`）。
- [ ] meta 损坏时列表仍可用，该条目被标记为「概要损坏」且不崩溃。

## 会话恢复

- [ ] 在 JSONL 中间插入一行非法 JSON，`/resume` 后该行被跳过、其余消息完整恢复，并显示「跳过 1 行」。
- [ ] 末尾存在含 `tool_calls` 但无对应 `tool_call_id` 工具消息的 assistant 消息时，恢复截断到该消息之前（最后完整轮次），不把悬空调用发给模型。
- [ ] 完整会话 `/resume` 后消息顺序与条数和存档一致，且可继续走 `prepare_request`。
- [ ] 恢复后估算 token 超过 131,072 × 0.8 时先执行一次压缩，压缩成功后最早轮次被摘要消息替换。
- [ ] 压缩失败或压缩后仍超限时，从最旧完整轮次截断直到估算 ≤ 52,429，保留指令消息与最近一轮，恢复报告包含截断条数。
- [ ] 距上次活跃超过 4 小时恢复时，对话开头插入一条时间跨度提醒消息。
- [ ] 距上次活跃不超过 4 小时恢复时，不插入提醒消息。

## 自动笔记

- [ ] 每完成 3 个用户轮次后触发一次笔记 LLM 调用（用伪 LLM 断言调用次数为预期值）。
- [ ] 用户消息包含身份/偏好/纠正强信号（如「我是…」「我喜欢…」「不要…」）时，当轮立即触发一次笔记调用（用伪 LLM 断言），不必等到轮数阈值。
- [ ] 应用退出时（卸载钩子）触发一次笔记调用。
- [ ] 笔记调用超时（默认 10 秒）或失败时静默丢弃，不阻塞、不中断退出。
- [ ] 笔记请求中 tools 为空（断言请求无工具定义）。
- [ ] 用户身份、用户偏好、纠正反馈写入 `~/.zxcode/notes.md`；项目知识、参考资料写入 `.zxcode/notes.md`（项目根下）。
- [ ] 笔记写入为原子替换：写入前后文件均为可解析文本，不存在半写状态。
- [ ] 代码库中不存在本地相似度去重实现（无编辑距离、向量、嵌入等依赖），去重仅依赖 LLM 输出。
- [ ] 退出时生成的一句话摘要成功时写入 meta 的 summary 字段；失败时字段为空且无报错。

## 命令

- [ ] `/notes` 可查看项目级与用户级笔记的内容与文件路径。
- [ ] `/notes clear` 默认清空项目级笔记，需确认，确认后文件内容为空。
- [ ] `/notes edit` 打开系统默认编辑器，或打印可编辑的绝对路径。
- [ ] `/sessions` 列表只显示概要信息（id、标题、消息数、时间）。
- [ ] `/resume ` 弹出会话选择列表，按时间排序。
- [ ] `/sessions delete <id>` 删除对应的 jsonl 与 meta 文件，需确认。
- [ ] `/sessions clear` 清空全部会话文件，需确认。
- [ ] `/sessions path` 打印会话目录的绝对路径。

## 回归与端到端

- [ ] 全量单测通过：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v` 无失败。
- [ ] 现有 `/help`、`/clear`、`/model`、`/plan`、`/compact`、`/exit` 相关测试仍通过，行为无回归。
- [ ] 端到端：伪 LLM 流跑通「新会话注入指令 → 3 轮对话 → 退出存档 → 重启 `/resume` 恢复 → 继续对话」，恢复后首条请求包含指令消息且消息数正确。
