# ZXCode 上下文记忆系统规格

## 背景

ZXCode 目前的所有会话状态都保存在内存里：`ChatSession` 只持有当前进程内的消息列表，关闭终端后一切丢失；模型每次请求看到的项目上下文只有系统提示词和环境消息，项目自己的编码规范、技术栈说明没有稳定的注入通道。与此同时，压缩机制已经可以自动控制历史体积，但缺少「跨进程恢复」和「长期记忆」两个环节。

本章要把三块能力合起来，构成 ZXCode 的上下文与记忆层：

1. 项目/用户指令文件：让新会话自动带上项目的约定和用户个人的偏好；
2. 会话 JSONL 存档与恢复：让对话可以跨进程续上，且崩溃只丢最后一行；
3. 自动笔记：让 LLM 定期把对话中的偏好、纠正、项目知识沉淀成文件，跨会话复用。

## 目标用户

- 在 Windows 终端里用 ZXCode 处理多个本地项目的开发者，希望每个项目自动带上各自的编码规范与注意事项，不用每次口头交代。
- 希望中断后能原样恢复会话、且不在乎偶尔一条坏数据的用户。
- 希望助手能记住自己的偏好和纠正、并跨会话持续生效，而不想手动维护笔记的用户。

## 能力清单

- 项目级指令文件：新会话启动时自动读取项目根目录的指令文件，作为一条独立消息注入对话开头。
- 用户级指令文件：用户目录的指令文件同样被读取，拼在项目级内容之后。
- 固定优先级：项目级内容排在用户级内容之前，高优先级内容先被模型看到、优先遵循。
- 模块化引用：指令文件支持以行为单位引用其他 Markdown 文件，相对路径以被引用文件所在目录为基准。
- 引用安全：嵌套深度受限，循环引用、路径逃逸、跨层级引用一律拦截并给出可见警告，跳过违规行但不中断启动。
- 会话 JSONL 存档：每条消息作为一个 JSON 对象追加写入一行，追加是常数开销，崩溃最多丢失最后一行不完整数据。
- 会话概要文件：每个会话另存一个小文件记录 ID、标题、摘要、消息数、时间与模型，会话列表只读概要、不扫全量日志。
- 会话恢复：恢复时跳过解析失败的行；末尾存在未配对工具调用的消息时，截断到最后完整位置。
- 恢复体积控制：恢复后的上下文超过窗口时先触发一次压缩，仍超限则从最旧轮次截断，并保留边界提示。
- 空闲提醒：距上次活跃超过阈值时，恢复后插入一条时间跨度提醒消息。
- 自动笔记：每隔固定轮数、应用退出时，以及用户消息出现身份/偏好/纠正等强信号时，异步调用 LLM 把最近对话整理进固定类别的笔记；去重由 LLM 判断，不实现本地相似度算法。
- 笔记分级存储：用户身份、用户偏好与纠正反馈写入用户级笔记；项目知识与参考资料写入项目级笔记。
- 笔记命令：提供查看、清空、定位编辑笔记的命令。
- 会话命令：提供列出、恢复、删除、清空、定位会话文件的命令。

## 非功能要求

- **崩溃安全**：会话追加写入与概要更新都必须原子、可恢复；坏数据不得让恢复流程整体失败。
- **安全边界**：指令文件内容只作为纯文本注入，不执行、不渲染；引用解析必须防路径逃逸与循环；跨层级引用默认禁止。
- **上下文效率**：会话列表不扫描完整日志；恢复后的上下文必须回到窗口之内；指令文件有大小上限，超限截断并提示。
- **响应性**：笔记与摘要都在后台异步执行，不阻塞对话主循环；退出时的后台任务有超时，超时或失败静默丢弃。
- **可观测性**：恢复报告包含跳过行数、截断位置、压缩或截断动作；笔记更新记录时间与涉及类别。
- **兼容性**：现有 `/clear`、`/compact`、`/plan`、模型切换行为不回归；消息格式保持与模型服务商兼容；恢复后的会话继续走现有压缩与工具循环。
- **可测试性**：全部恢复与笔记场景可用临时目录和伪 LLM 流复现，不依赖真实 API。

## 设计骨架

### 指令文件层

启动时按「项目级在前、用户级在后」的顺序读取指令文件，先展开各自的模块化引用，再合并成一条独立指令消息。该消息插在稳定系统提示词与环境消息之后、对话历史之前；新会话与清空会话后都会注入。指令内容保存在会话对象的独立字段中，不写入会话存档；恢复会话时按当前指令文件重新注入，避免与存档重复。现有的项目提示词目录机制保持不变，两者并存。

### 会话存储层

以会话 ID 为键，把内存消息逐条追加到 JSONL 文件；每轮提交后原子刷新概要文件。概要文件是会话列表的唯一数据源。

### 恢复层

逐行解析存档：坏行跳过并计数；检测末尾悬空的工具调用并截断到最后完整轮次；随后做体积检查，超限先压缩、仍超限再截断；最后按空闲时长决定是否插入提醒。恢复完成后生成统计报告，并把消息交给现有会话与压缩流程继续使用。

### 笔记层

维护轮次计数，达到阈值、应用退出，或检测到用户消息中的身份/偏好/纠正强信号时，异步调用 LLM（不带工具）读取当前笔记与最近对话，按固定五类产出增量更新：用户身份、用户偏好、纠正反馈写入用户级文件；项目知识、参考资料写入项目级文件。写入采用原子替换。去重完全依赖 LLM 输出。退出时若同一调用成功，顺带生成一句话会话摘要写入概要文件。

### 命令层

新增的命令接入现有斜杠命令分发；清空、删除类操作复用现有确认弹窗；所有命令的展示都来自概要文件或笔记文件，不扫描完整日志。

## 完成定义

- 新会话第一条请求中可见注入的指令内容，优先级顺序固定为项目级在前、用户级在后。
- 所有引用违规都能被拦截并可见警告，且不影响启动。
- 会话持续追加存档，崩溃后恢复只丢最后一行，坏行跳过，悬空工具调用被截断。
- 会话列表只依赖概要文件；恢复后的上下文不超过窗口，并有明确动作报告。
- 自动笔记按固定类别写入正确层级文件，去重不依赖任何本地相似度实现。
- `/notes` 与 `/sessions` 命令可完成查看、清空、定位（及会话恢复/删除）。
- 现有命令与压缩行为无回归，`docs/memory/checklist.md` 全部适用项可勾选。

## Out of Scope

- 不实现笔记相似度去重算法，去重完全交给 LLM。
- 不做会话全文搜索。
- 不做云同步与跨项目共享笔记。
- 不做指令文件热重载与目录监听，改动在新会话或重载命令后生效。
- 不迁移、不重写现有的项目提示词目录机制。
- 不做会话导出为其他格式（文本、HTML 等）。
- 不支持指令文件的执行、渲染或除 Markdown 外的格式。
- 不做同一会话的多进程并发写入与文件锁。
