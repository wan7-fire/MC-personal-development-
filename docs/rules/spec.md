# ZXCode 规则引擎系统规格

## 背景

ZXCode 已有安全策略、Skill、命令等扩展机制，但这些机制各自独立：安全策略管工具放行，Skill 管 SOP 注入，命令管交互入口。缺少一种通用的、由用户声明式定义的自动化能力：在会话、轮次、消息、工具等生命周期节点上，按条件自动执行动作（拦截、注入提示词、执行命令、发请求）。

规则引擎把这类行为统一为「事件 + 条件 + 动作」三要素：监听某个生命周期事件，条件命中时执行一组动作；工具执行前的规则可以拦截调用，并把拒绝原因作为工具结果回馈给 LLM，形成「拦截 → Agent 收到原因 → Agent 调整策略」的闭环。Hook 自身任何失败都只记日志，绝不中断 Agent 主流程。

## 目标用户

- 想给 ZXCode 加自动化行为（如每次写文件前检查路径、收到特定消息自动注入提示词）的终端用户。
- 想用 YAML 维护项目级/团队级规则的开发者。
- 想基于工具参数做细粒度安全拦截的维护者。

## 能力清单

- 规则由「事件 + 条件 + 动作」三要素描述；条件可省略表示无条件触发，事件和动作必须存在。
- 生命周期事件覆盖四个层级：会话级、轮次级、消息级、工具级，外加少量系统级事件。
- 工具执行前的事件具备拦截能力，可基于工具参数做细粒度决策；被拦截后拒绝原因作为工具结果回馈给 LLM。
- 条件表达式复用权限规则的匹配语法，支持精确、反向、正则、glob 四种操作符。
- 条件逻辑组合只有「全部满足」或「任一满足」二选一，禁止混用，避免引入运算符优先级和完整表达式引擎。
- 四种动作执行器：command、prompt、http、agent（占位）。
- 执行控制三件套：只执行一次、后台异步执行、动作超时；pre_tool_use 拦截事件强制不允许异步。
- 动作模板支持上下文变量占位，未定义变量替换为空串而不是报错。
- Hook 自身执行失败只记日志，不中断 Agent 主流程。
- 从 YAML 声明式加载规则，加载时集中校验事件名、动作类型、reject 使用位置、异步标记、各动作必填字段，非法配置能定位到具体规则。
- 引擎嵌入 Agent Loop 的关键节点：会话起止、轮次起止、消息发送前/接收后、工具执行前（同步、可拦截）、工具执行后。

## 非功能要求

- **确定性**：同一规则集在相同事件序列下行为一致；规则按声明顺序求值，拦截结果稳定可复现。
- **性能**：无规则命中时 Hook 开销可忽略，不得为每条消息引入明显延迟；事件到规则的查找必须常数级。
- **安全**：command 与 HTTP 动作沿用项目现有安全策略与确认流程，不放宽现有边界；reject 只允许出现在 pre_tool_use。
- **可观测性**：每次 Hook 触发、跳过、失败、超时都有日志，日志携带规则标识，且日志写入失败不影响主流程。
- **错误隔离**：规则解析期之外的任何运行时错误都被引擎捕获，只记日志并继续；动作失败不污染工具结果（拦截决策除外）。
- **兼容性**：不改变现有会话、压缩、Skill、命令、MCP 的行为；既有测试保持通过。
- **错误定位**：加载期校验失败的错误信息必须包含规则文件路径与 Hook（规则）标识。

## 设计骨架

### 规则文件与加载

- 规则以 YAML 文件声明，存放于项目 `.zxcode/rules/` 目录；后续可扩展用户级目录。
- 一个文件可含多条规则，每条规则有唯一标识（文件内不得重复）。
- 加载时集中校验，任一非法规则导致整体加载失败并给出定位，不静默跳过——规则是全局行为，宁可失败也不半载。
- 校验项：事件名必须在事件目录内、动作类型必须是 command/prompt/http/agent 之一、reject 只能用于 pre_tool_use、async 不能用于 pre_tool_use、每种动作类型的必填字段齐全。

### 事件目录

- 会话级：session_start、session_end。
- 轮次级：turn_start、turn_end。
- 消息级：pre_message、post_message。
- 工具级：pre_tool_use（可拦截）、post_tool_use。
- 系统级：system_startup、system_exit、system_error、system_compact。

### 条件

- 条件由「上下文字段 + 操作符 + 值」构成。
- 操作符四种：精确匹配、反向匹配、正则匹配、glob 匹配。
- 组合方式二选一：全部满足或任一满足；同一组条件内不允许混用两种组合。
- 可匹配的上下文字段包括：事件名、工具名、工具参数字段、消息内容、文件路径、错误信息等。

### 动作

- command：在项目环境执行一条命令，输出记录到日志；必填 command 字段。
- prompt：向当前对话注入一条提示词消息（可作为用户消息或系统提示）；必填 prompt 字段。
- http：向指定地址发起一次请求；必填 url 字段。
- agent：启动一个子 Agent（本期占位，返回未实现结果，不实际启动）；必填 name 字段。
- 动作模板支持上下文变量占位，覆盖事件名、工具名、文件路径、消息内容、错误信息、工具参数字段；未定义变量替换为空串。

### 执行控制

- once：同一会话内每条规则最多执行一次，跨轮次生效；重启 ZXCode 即新会话，once 状态不持久化，需要会话开始初始化的逻辑应挂在 session_start 事件上。
- async：动作在后台异步执行，不阻塞主流程；拦截事件禁止 async，加载期即报错。
- timeout：动作超过时限即终止并记日志，不中断主流程。

### 拦截

- reject 只允许声明在 pre_tool_use 事件上。
- 规则命中且声明 reject 时，产生拒绝决策；拒绝原因作为该工具调用的错误结果返回给 LLM，工具本体不执行。
- 命中拦截的规则不再执行该规则的动作；多条规则命中时按声明顺序，第一个拒绝决策生效。
- 拦截求值必须同步完成，不进入后台队列。

### 错误隔离

- 引擎捕获 Hook 执行期间的所有异常与超时，记录日志后继续主流程。
- 动作执行失败不改变本轮消息与工具结果；只有拦截决策本身可以改变工具结果。

### 集成点

- Agent Loop：会话起止、轮次起止、消息发送前/接收后。
- 工具调度器：工具执行前（同步、可拦截）、工具执行后。
- 应用初始化：启动时加载规则集，并提供查看与重载的管理入口。

## Out of Scope

- 完整表达式引擎与运算符优先级（条件组合明确禁止混用）。
- agent 动作的实际执行（本期占位）。
- 规则的市场、分发与版本管理。
- 图形化规则编辑器。
- 跨进程/分布式规则共享。
- 条件对历史对话的任意检索（仅能访问当前事件上下文）。
- 规则文件的热监听自动重载（本期通过管理命令手动重载）。
