# ZXCode Skill 系统规格

## 背景

ZXCode 目前通过固定稳定提示词、项目/用户指令文件和 MCP 工具扩展能力。功能变多之后，把「一段可复用的 SOP + 配套工具 + 元信息」写死在代码里会越来越难维护，全部塞进启动提示词又会显著增加每次请求的固定开销。

Skill 系统把这类能力包装成可分发、可热更新、按需加载的单元：启动时只暴露「名字 + 一句话说明」给模型，模型判断需要时再通过系统级加载工具把完整指令和专属工具带进当前会话；同时通过工具白名单落实最小权限。

## 目标用户

- 使用 ZXCode 完成日常开发，希望把常用流程（提交、审查、测试等）固化成可复用 SOP 的终端用户。
- 希望给项目或本机增加专属能力，而不修改主程序代码的开发者。
- 希望维护 ZXCode 内置能力包，并给后续版本提供参考模板的实现者。

## 能力清单

- Skill 用 YAML frontmatter 加 Markdown 正文描述，frontmatter 承载元信息，正文是发给模型的 SOP 指令。
- Skill 按项目级、用户级、内置三级存放，同名按优先级覆盖，解析失败的单个文件跳过并记录，不阻断整体加载。
- 启动阶段只把每个 Skill 的名字和一句话说明注入对话，完整指令不进入启动上下文。
- 模型可通过系统级加载工具按需激活 Skill，加载后完整指令固定进入环境上下文。
- 激活后的完整指令不写入普通消息历史，而是在每轮 Agent 循环重建时保持在显眼位置。
- 多个共享模式的 Skill 可以同时激活，各自指令按激活顺序并存。
- 共享模式下 Skill 在当前对话上下文内继续执行，执行结果留在主对话历史。
- 隔离模式下 Skill 在独立对话中执行，执行完成后只把结果摘要回流到主对话。
- 隔离模式可按 Skill 声明携带全部历史、仅最近若干条历史或完全不携带历史。
- Skill 可声明可见工具白名单，收窄模型可见工具集，白名单缺失工具按静态/动态两种时机校验。
- 系统级加载工具不受白名单约束，始终可用，支持 Skill 之间嵌套触发。
- 目录型 Skill 可在同一目录携带自己的工具 schema 与工具实现脚本，整体作为一个可分发能力包。
- Skill 加载后自动注册成短命令出现在帮助里，并提供管理命令查看列表、详情和强制重新扫描。
- Skill 执行时重新读取源文件，支持热更新。
- 清空对话会同时清掉已激活 Skill，避免 SOP 残留到新对话。
- 内置 commit、review、test 三个 Skill 样板，覆盖共享与隔离两种模式。

## 非功能要求

- **确定性**：相同 Skill 源文件在相同环境下扫描、解析和注入顺序必须稳定；多个激活 Skill 按固定激活顺序排列。
- **最小权限**：Skill 只能收窄工具集，不能扩大工具集；未声明白名单时保持当前全部工具可见。
- **安全边界**：Skill 不能放宽现有安全策略、确认弹窗或写操作拦截；系统级加载工具始终保留。
- **故障隔离**：格式解析失败的单个 Skill 跳过并记录；白名单静态缺失工具要快速失败并给出可定位的错误。
- **兼容性**：现有指令文件、MCP、会话存档、上下文压缩、plan-only 模式和工具安全策略继续按原行为工作。
- **可观测性**：跳过、校验失败、激活失败和重扫结果都要有可读提示或日志，不能静默吞掉。
- **性能**：启动只解析元信息并注入索引，不加载完整正文；完整正文只在激活时读取。
- **最小改动**：优先复用现有工具执行器、安全确认、会话拼装和 Agent 循环，不重写主流程。

## 设计骨架

### Skill 文件格式

单个 Skill 由 frontmatter 和 Markdown 正文组成。frontmatter 必须包含唯一名字、一句话说明和执行模式；可选声明所用模型、上下文携带策略、最近历史条数和可见工具白名单。正文是激活后注入给模型执行的 SOP。

### 存放与优先级

Skill 分别从项目级目录、用户级目录、内置资源三层扫描。同名的 Skill 按「项目 > 用户 > 内置」覆盖；被覆盖的低优先级文件不参与索引。单文件 Skill 和目录型 Skill 都支持，目录型 Skill 的入口 Markdown 与工具文件放在同一目录。

### 两阶段加载

第一阶段在启动时扫描全部三层，只保留每个 Skill 的名字、说明、来源层级和校验状态，把名字加说明组装成一条「可用 Skill 索引」注入对话。第二阶段由系统级加载工具触发：按名字重新读取源文件，解析完整 frontmatter 和正文，加载目录型工具，校验动态白名单，然后执行激活动作。

### 环境上下文

激活后的完整指令作为独立系统消息钉在环境上下文里，位置在稳定全局规则之后、运行时环境信息之前；每轮 Agent 循环重建请求时都重新注入。指令不追加进普通消息历史，因此在压缩、存档和恢复会话时不会残留。多个共享 Skill 同时激活时按激活顺序排列。

### 执行模式

- **共享模式**：激活动作把完整指令挂入当前会话的环境上下文，Agent 在当前循环内继续执行，工具结果和最终回答留在主对话历史。
- **隔离模式**：激活动作立即启动一个临时独立对话，携带 Skill 指令和按策略选择的主对话历史；执行完成后把结构化结果摘要作为工具结果回流主对话。隔离对话不写入普通会话存档，完整 SOP 不留在主对话环境上下文。

上下文携带策略只对隔离模式生效：全部历史、最近若干条、完全不携带。未指定时使用默认最近条数。

### 工具白名单

Skill 可以在 frontmatter 中声明可见工具白名单。未声明时视为「全部工具可见」；声明后，当前模型请求的工具定义为所有激活 Skill 白名单的并集，再加系统级加载工具。目录型 Skill 自带工具在扫描时可识别；除此之外，白名单中的每个工具必须在启动扫描时已存在于工具注册表，缺失立即快速失败。

### 目录型 Skill 工具

目录型 Skill 的入口 Markdown 旁可放工具 schema 文件与实现脚本。工具 schema 描述名字、说明、参数、只读属性和超时；实现脚本按约定从标准输入接收参数并向标准输出返回结果。工具执行复用现有 schema 校验、超时、输出截断和确认弹窗，且无论声明只读与否，执行前都经过项目安全策略裁决：默认模式要求确认，allow 模式直接放行，strict 模式无规则即拒绝。脚本与 skill 文件均做符号链接 containment 检查，解析到所属根目录之外的文件不加载。项目级与用户级目录型 Skill 的脚本在激活时需要用户显式授权，内置级 Skill 默认可信；未授权时激活失败，脚本不会被加载或执行。

### 命令与生命周期

提供管理命令查看已加载 Skill 列表、查看单个 Skill 详情、强制重新扫描。每个已扫描 Skill 自动注册成短命令；执行短命令时重新读取源文件并按其模式启动。清空对话时清除全部激活 Skill。热更新通过「执行时重读源文件」和「强制重扫」两条路径实现。

### 集成点

Skill 系统接入现有的会话请求拼装、Agent 循环工具定义、命令注册表和应用初始化流程。系统级加载工具注册进全局工具注册表，但不在任何白名单过滤中隐藏；共享模式复用当前 Agent 循环，隔离模式复用同一个模型客户端和工具执行边界。

## 完成定义

- 启动时能看到 Skill 索引，且索引只含名字和一句话说明。
- 系统级加载工具能激活共享与隔离两种模式的 Skill，并正确处理动态白名单缺失。
- 共享 Skill 的完整指令固定在环境上下文，不进入普通历史，可多 Skill 并存。
- 隔离 Skill 能按三种历史策略执行，并把含结论、变更、未决问题和状态的结构化摘要回流。
- 工具白名单在模型请求中实际生效，系统级加载工具始终可见。
- 目录型 Skill 自带工具能加载、校验、执行并复用超时与确认机制。
- 管理命令、短命令、热更新和清空对话行为符合本章描述。
- 内置 commit、review、test 三个样板可运行，覆盖两种模式。
- 自动化测试和手工端到端验证通过。

## Out of Scope

- Skill 的市场与分发机制。
- Skill 的版本管理与依赖解析。
- Skill 之间的显式工具依赖声明（除嵌套加载外）。
- 不可信第三方 Skill 的沙箱隔离。
- 除 Python 外的工具实现语言。
- 图形化 Skill 编辑器。
- 把隔离对话作为普通会话持久化到会话存档。
- 对尚未注册的外部/动态工具（如启动阶段未连接的 MCP 工具）的白名单支持。
