# MewCode 六核心工具与 LLM 工具循环规格

## 背景

MewCode 已具备 OpenAI-compatible LLM 流式对话、内存会话和 Textual 终端界面，但模型目前只能输出文本，不能读取项目、搜索代码、修改文件或执行命令。下一阶段需要在现有聊天链路中加入一个最小、可控的工具运行时，让模型能够通过正式的工具调用协议完成真实编程任务，同时避免路径逃逸、覆盖并发修改、半写文件和无限工具循环。

## 目标用户

- 在 Windows PowerShell 或 Windows Terminal 中使用 MewCode 处理本地代码项目的开发者。
- 使用支持 OpenAI-compatible tool calling 的模型与服务商的用户。
- 希望在执行文件修改和命令前获得清晰安全边界的用户。

## 目标

- 让模型能够读取、创建、编辑、搜索项目文件并执行受控 PowerShell 命令。
- 让所有工具共享一致的注册、调度、超时、错误和结果语义。
- 让工具调用能够嵌入现有流式多轮对话，并在获得工具结果后继续推理直至最终回答。
- 在不增加新运行依赖的前提下提供可测试、可维护的首版实现。

## 能力清单

- `ReadFile` 在项目边界内读取 UTF-8 文本，并支持按行截取和带行号返回。
- `WriteFile` 可以创建文本文件，并在覆盖现有内容时通过确认和内容指纹防止误覆盖。
- `EditFile` 可以一次提交多段精确文本替换，并保证全部成功或全部不写入。
- `Bash` 在 Windows 上执行非交互式 PowerShell 命令，并对危险或无法可靠判断的命令请求单次授权。
- `Glob` 在指定搜索根目录下查找文件，自动忽略无意义的大型目录并优先返回最近修改的结果。
- `Grep` 使用正则表达式搜索项目内文本，并报告匹配位置。
- 所有内置工具通过统一工具契约暴露描述、输入约束、操作属性和执行结果。
- 注册表显式管理六个内置工具，拒绝名称冲突，并向 LLM 导出工具定义。
- 执行器并发处理同批只读调用，在全部读取结束后按原顺序串行处理写调用。
- 执行器把未知工具、参数问题、授权拒绝、超时和运行异常转换为结构化结果。
- 超出上下文预算的工具输出会被安全截断，并通过元数据告知模型。
- LLM 工具循环把工具调用和对应结果写回会话，直至模型给出最终文本或终止器停止循环。
- 用户可以取消正在进行的模型流或工具执行，且不会把残缺回答提交到后续会话。

## 非功能要求

- **路径安全**：所有文件类工具只能访问当前工作目录子树，必须拒绝路径穿越、根目录外绝对路径和符号链接逃逸。
- **数据完整性**：覆盖和编辑必须检测内容冲突，文件变更必须以原子方式提交，校验或授权失败不得改变目标文件。
- **最小授权**：创建新文件可以直接执行；覆盖、编辑以及危险或不确定的命令必须由用户明确批准。
- **响应性**：模型流、只读工具并发、超时和取消不能阻塞终端界面刷新。
- **上下文效率**：文件大小、搜索结果和工具输出都必须受限，避免无界内容进入模型上下文。
- **兼容性**：首版面向 Windows PowerShell，只处理 UTF-8 文本，并保持现有 OpenAI-compatible 配置方式。
- **可观测性**：工具结果和日志应包含定位问题所需的类别、调用标识、耗时和截断信息，但不得记录 API Key 或完整敏感内容。
- **可测试性**：核心行为应能通过临时目录、伪造 LLM 流和无头 Textual 测试重复验证，不依赖真实 API。
- **可维护性**：优先复用现有会话、终端和循环终止逻辑，并使用 Python 标准库实现文件、搜索、并发和进程控制。

## 设计骨架

### 工具契约与注册表

工具契约定义所有工具共有的身份、说明、输入约束、操作属性、超时能力和异步执行行为。注册表只负责显式注册、重名检查、按名称查询和导出 LLM 可理解的工具描述，不承担工具创建、自动发现或依赖注入。

### 执行器

执行器是唯一执行入口，负责查找工具、校验参数、应用超时与授权、调度批量调用、归一化结果和响应取消。同批只读调用可以并发；写调用必须等待读取全部结束后按模型给出的顺序执行。单个调用失败不应让同批其他调用丢失结果。

### 文件与搜索边界

文件工具共享同一套真实路径和文本读取边界。读取只返回所需内容；覆盖使用内容指纹检测竞争修改；多段编辑基于编辑前快照定位互不重叠的唯一匹配，并通过临时文件替换实现事务式提交。搜索工具复用相同文件边界，各自应用已确认的忽略和数量规则，并返回有界、稳定、适合送回模型的文本结果。

### 命令执行与授权

命令工具只自动执行能够明确证明为项目内只读操作的窄范围 PowerShell 命令。写入、删除、下载、进程启动、重定向、动态表达式和其他不确定命令进入单次确认；明确越过项目边界或试图创建持久后台进程的命令直接拒绝。该策略是保守的应用层保护，不替代完整操作系统沙箱。

### LLM 工具循环

每轮请求携带会话消息和注册表导出的工具定义。普通文本继续流式显示；完整工具调用交给执行器，并以对应调用标识把结果加入会话后再次请求模型。循环复用现有终止策略处理最大轮次、重复观察、重复错误、无进展和用户取消。没有工具调用时，完整文本作为本轮最终回答提交到会话。

### 终端交互

现有 Textual 工作台继续负责输入、流式输出、状态和取消。需要授权时，界面显示工具类型、目标或命令及风险原因；每次批准只适用于当前调用。工具状态与最终回答位于同一会话体验中，但内部工具消息不伪装成普通用户或助手消息。

## 完成定义

- 六个核心工具均能通过注册表被模型发现并通过统一执行器调用。
- 文件、搜索、命令、超时、授权、取消和结构化错误行为均通过自动化测试。
- 伪造 LLM 流能够完成一次“工具调用—工具结果—最终回答”的完整循环。
- 真实兼容 API 能在终端中完成至少一次读取工具调用和后续自然语言回答。
- 原有纯文本流式对话、快捷键、命令和多轮会话行为没有回归。
- `docs/checklist.md` 中所有适用验收项均可观察并勾选。

## Out of Scope

- 插件自动发现、第三方工具加载、工厂、依赖注入容器和 Hook 框架。
- plan-only 模式、持久权限规则、整会话 Bash 全量授权和复杂策略配置语言。
- Linux、macOS、CMD、WSL 或其他 Shell 的首版支持。
- 二进制文件、非 UTF-8 文本、图片、音频和富媒体工具结果。
- 持久后台进程、交互式命令、PTY 会话和长驻服务管理。
- 会话落盘、工具结果缓存、跨进程恢复和分布式执行。
- 完整 Windows 系统沙箱或对已获用户批准命令的操作系统级隔离。
- 自动回滚已经成功完成的外部副作用。
- 从模型文本中猜测或解析工具命令作为协议降级方案。
