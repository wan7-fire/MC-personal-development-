# ZXCode 子工作者系统规格

## 背景

ZXCode 已有 Hook 规则引擎、Skill、命令等能力，但缺少「可并行、可后台、可复用的子任务执行单元」。目前的工具调用都在同一对话上下文里串行完成，遇到需要长时间探索、独立规划或并行验证的场景，会阻塞主对话且无法复用稳定的角色能力。

子工作者系统把「子 Agent」包装成一个统一的工具入口：通过类型参数选择预定义角色，工具列表保持稳定，不随角色增减变化。支持定义式（空白对话 + 固定角色）与 Fork 式（继承父对话历史）两种创建模式，并提供后台任务管理器，让子任务在后台运行、完成后以结构化通知异步回流主对话。

## 目标用户

- 想让 ZXCode 并行执行探索、规划、验证等子任务的终端用户。
- 想用 Markdown + YAML frontmatter 定义团队/项目级角色的开发者。
- 想限制子工作者能力边界（工具白/黑名单、嵌套防线、后台白名单）的维护者。

## 能力清单

- 子工作者统一由一个工具入口创建，通过类型参数选择角色，工具列表不随角色变化。
- 角色用 Markdown + YAML frontmatter 定义，包含角色名、用途、工具白/黑名单、模型、最大轮次、权限模式。
- 角色加载来源按优先级覆盖：项目目录 > 用户级 > 内置 > 插件；同名角色高级别覆盖低级别。
- 两种创建模式并存：定义式（空白对话 + 固定角色，可指定独立模型）与 Fork 式（继承父对话历史 + 复用父工具集，首请求命中 prompt cache）。
- 运行时状态隔离：消息历史、权限审批记录、文件读缓存、token 计数；基础设施共享：LLM 客户端、Hook 引擎、文件系统。
- 子工作者以「跑到底」模式执行：任务从参数注入，不等待用户输入；LLM 不再调用工具即视为完成，最后一条文本作为结果返回；Hook 在子工作者中仍然生效。
- Fork 路径在第一条用户消息注入强硬指令：不能再次 Fork、不主动对话、不请求确认、直接使用工具、最终报告控制字数并按结构化字段输出。
- 工具过滤多层防线：全局禁止列表排除工具自身（防嵌套），自定义角色额外限制，后台运行的子工作者叠加更严格白名单。
- 后台运行三种进入路径：显式指定、前台超时自动切换、用户手动切换；Fork 模式强制后台；前台转后台时移交运行中实例，不杀掉重来。
- 后台任务管理器维护任务状态、结果、token 用量、起止时间；完成后通过结构化通知异步注入主对话，不打断当前对话。
- 内置多种常用角色（代码探索、计划制定、通用全能），验证角色用配置开关按需启用；配套斜杠命令查看和管理后台任务。

## 非功能要求

- **稳定工具面**：无论新增或删除多少角色，模型可见的工具列表保持一致，只有一个子工作者入口。
- **缓存友好**：Fork 模式的首个请求与父对话前缀一致，命中 prompt cache；不得在前缀中插入可变内容。
- **隔离正确性**：子工作者的历史、审批记录、读缓存、token 计数互不污染；共享的客户端、Hook 引擎、文件系统按原语义工作。
- **嵌套防护**：任何路径（定义式、Fork 式、后台）都不允许再创建子工作者，全局禁止列表始终生效。
- **不阻塞主对话**：后台任务不得阻塞主流程；完成通知异步注入，且不改变当前轮次状态。
- **可观测性**：任务状态迁移、token 用量、起止时间、完成/失败原因均可查询；失败原因结构化返回。
- **兼容性**：现有会话、压缩、Skill、Hook、命令行为不变；子工作者中的 Hook 与权限策略照常生效。

## 设计骨架

### 统一工具入口

- 系统注册唯一一个子工作者工具，工具定义不依赖角色集合。
- 工具参数包含：目标角色（可省略表示 Fork 式）、任务描述、创建模式（定义式/Fork 式）、模型覆盖、后台标记等。
- 工具执行结果包含：任务标识、状态、结果文本、token 用量、耗时；后台任务返回任务标识并立即结束工具调用。

### 角色定义与加载

- 角色文件为 Markdown + YAML frontmatter：frontmatter 承载角色名、用途说明、工具白/黑名单、模型、最大轮次、权限模式；正文是注入子对话的系统提示。
- 角色目录按优先级扫描：项目级、用户级、内置、插件；同名按高优先级覆盖，低优先级同名校验失败不参与索引。
- 解析失败或校验失败的单个角色文件跳过并记录日志，不阻断整体加载。
- 插件来源本期仅约定目录与优先级，实际插件机制接入留待后续。

### 创建模式

- **定义式**：新建空白对话，注入角色系统提示与任务描述，使用角色声明（或覆盖）的模型与工具集；运行到「不再调用工具」即结束，最后一条文本作为结果。
- **Fork 式**：不指定角色时启用；克隆父对话历史并复用父工具集；在克隆历史最前面注入 Fork 强硬指令；强制进入后台。

### 隔离与共享边界

- 隔离：消息历史、权限审批记录、文件读缓存、token 计数均按子任务独立维护。
- 共享：LLM 客户端、Hook 引擎、文件系统与主对话共享。

### 跑到底执行

- 任务描述直接作为用户消息注入，不进入交互等待。
- 完成判定：模型返回的助手消息不包含工具调用即为完成；取该消息文本作为结果。
- 超限或异常按失败结束，返回结构化失败原因。
- Hook 引擎在所有子工作者中生效，拦截与注入行为与主对话一致。

### 工具过滤多层防线

- 全局禁止列表：子工作者工具自身始终不可见，任何角色与模式都不能覆盖，从源头阻断嵌套。
- 角色级限制：角色 frontmatter 可声明白名单或黑名单，收窄可见工具。
- 后台叠加：后台运行的子工作者在角色限制基础上再套一层更严格的白名单，默认只保留只读与搜索类工具。

### 后台任务管理

- 后台进入路径：调用时显式指定、前台运行超过时间阈值自动切换、用户手动切换；Fork 式强制后台。
- 前台转后台：移交运行中的实例，不终止、不重启，保持同一任务标识。
- 任务管理器维护：任务标识、状态、结果、token 用量、起止时间；支持终止。
- 完成通知：结构化消息（任务标识、角色、状态、结果摘要、token、耗时）异步注入主对话，不打断当前轮次。

### 内置角色与管理命令

- 内置角色至少覆盖：代码探索、计划制定、通用全能。
- 验证角色默认关闭，由配置开关启用。
- 斜杠命令支持：列出后台任务、查看单任务详情、终止任务。

## Out of Scope

- 子工作者之间的消息通信与编排（本期仅父子关系）。
- 跨进程/分布式任务调度。
- 任务结果持久化与会话恢复（本期仅内存态）。
- 子工作者的沙箱隔离（文件系统与主对话共享）。
- 插件的实际加载机制（本期仅预留优先级与目录约定）。
- 角色市场与版本管理。
- 子工作者中的交互式确认流程（Fork 指令明确禁止请求确认）。
